You are acting as a principal game engineer, technical director, gameplay designer, systems designer, narrative designer, QA lead, and optimization engineer.

You are being given the complete source code for an existing browser-based 3D action RPG called **Legend of Peanits**, formerly called **Wildmoor**.

Your task is not to merely suggest changes.

Your task is to **directly edit, extend, refactor where necessary, debug, test mentally and structurally, and deliver a substantially upgraded 2.0 version of the game**.

The finished result should feel like a cohesive indie action RPG rather than a collection of disconnected systems.

Treat the existing game as valuable production code.

Do not throw it away.

Do not replace it with a simplified rewrite.

Do not remove functioning systems merely because they are complex.

Preserve the existing identity, controls, visual style, world, mechanics, characters, humor, atmosphere, lore, saves where reasonably possible, multiplayer where reasonably possible, and existing gameplay functionality.

The current codebase is approximately 14,700 lines in a single HTML file using Three.js and includes a large number of interconnected systems. It already contains, among other things:

The existing systems are already technically ambitious.

The primary problem to solve for 2.0 is not simply "add more features."

The problem is:

**The game has more mechanical breadth than narrative structure and progression structure.**

Your central design goal is therefore:

> Give the existing systems reasons to matter.

The game should emerge from this update as a **compact dark-folklore open-world action RPG with unusually expressive traversal, reactive settlements, local mysteries, exploration-driven progression, and a world that visibly remembers what the player has done.**

Do not turn it into a generic loot game, MMO, crafting simulator, survival game, or Ubisoft-style checklist.

Do not dilute its personality.

The game should feel handmade, strange, funny in places, melancholy in places, and increasingly supernatural as the story progresses.

# PART I — PRESERVE THE CORE IDENTITY

The player fantasy should remain:

- arrive as an outsider
- wander through an unusual medieval valley
- explore freely
- learn movement through play
- improve skills through use
- help villagers
- investigate strange events
- fight dangerous creatures
- discover secrets
- gradually become known throughout the valley
- uncover darker supernatural truths beneath apparently local problems

The overall design should favor:

- compact density over map size
- memorable locations over procedural emptiness
- meaningful progression over number inflation
- environmental storytelling over exposition dumps
- movement mastery over stat checks
- world-state changes over generic XP rewards
- strange local folklore over generic fantasy lore
- consequences the player can physically see

Preserve the existing humor and slightly rough personality where it feels intentional.

Do not sterilize the game into generic polished fantasy writing.

# PART II — MAIN STORY: TURN THE CURRENT GAME INTO A MULTI-ACT RPG

The existing story involving the King, the Hermit, the Beacon, Ysolde, Maren, Inquisitor Hale, the Black Pool, the Goblin King, the Old Bear, the fairy children, the mountain settlements, and the valley should be woven into a larger narrative.

Do not discard the existing mystery.

Expand it.

The central story should become approximately five acts.

## ACT I — THE CHAMPION

Preserve the existing early-game flow:

- player arrives
- meets important locals
- reaches the kingdom
- speaks to the King
- is directed toward the Hermit
- obtains what is necessary to relight the Beacon
- lights the Beacon
- is formally named Champion
- receives the existing early reward such as additional hearts

Use this act to naturally teach:

- movement
- combat
- blocking
- stamina
- quest interaction
- exploration
- sleeping/time
- goblins at night
- the world map
- skill leveling

Do not make the tutorial intrusive.

The game should teach by giving the player things to do.

After the Beacon is lit, do not simply end the major story guidance with "the valley is yours."

Use the Beacon as the event that reveals the larger problem.

The player should initially think the Beacon solved something.

Later they should realize it may also have awakened, exposed, or destabilized something.

# ACT II — THE BLACK POOL

Preserve and expand the Ysolde/Maren/Hale murder mystery.

Existing facts and tone should remain recognizable:

- Ysolde is dead
- Maren the herbalist is accused
- Hale is pushing the witchcraft explanation
- a pyre already exists
- villagers are uneasy
- Wick found the body
- Ysolde's father is grieving
- Ysolde's diary contains clues
- Hale is implicated
- Maren can ultimately be freed
- Hale can end up in the stocks

Do not reduce this to three obvious glowing quest items.

Improve the investigation.

Add more investigatory texture:

- physical evidence
- environmental evidence
- conflicting testimony
- optional evidence
- misleading but plausible evidence
- changes in NPC dialogue depending on discoveries
- clues that point toward Hale before proving it
- one or two pieces of evidence that suggest Hale may genuinely have encountered something supernatural

The player should feel like they solved it.

Possible evidence types:

- silver ring
- torn black cloth
- ritual marks
- diary page
- disturbed reeds
- footprints
- blood
- burned herbs
- Hale's private note
- a symbol matching something near the Black Pool
- an item belonging to Ysolde
- witness testimony
- evidence in Hale's room
- signs of something non-human in the water

Do not require every clue.

Use a threshold system.

For example:

- 3 strong clues can expose Hale
- more clues can unlock richer dialogue
- finding all evidence may unlock an alternate reward, lore revelation, or later branch

Hale should still confess once cornered, but his confession should strongly imply that his actions were connected to a real supernatural belief.

His existing idea that:

**"some things must be given to the dark so the light keeps"**

should become one of the major thematic pillars of 2.0.

He should be morally wrong.

He should not simply be insane.

There should be enough evidence that he discovered something real but responded to it monstrously.

Maren should be freed.

Hale should take her place in the stocks.

The settlement should visibly change after this.

See the world-state section later.

# ACT III — SOMETHING WAS LISTENING

After Hale is exposed, the player should initially feel victorious.

Then the Black Pool begins behaving differently.

This is the tonal shift.

Examples:

- strange fog appears near it
- animals avoid the area
- goblins become more active
- distant sounds come from underwater
- fairy rings behave differently
- Beacon light occasionally flickers
- villagers mention dreams
- some NPCs sleepwalk
- fish float dead
- birds disappear
- moonlight affects the pool
- black reeds begin growing
- unusual enemies appear
- the Hermit becomes alarmed
- Maren recognizes symbols Hale was using
- old village lore suddenly becomes relevant

The revelation:

Hale's sacrificial interpretation was evil, but his core belief that something beneath or beyond the Black Pool was being held in check was not entirely fabricated.

Do NOT make this a simplistic "Hale was right all along."

He was not.

Instead:

He discovered a real phenomenon and responded with superstition, murder, authoritarianism, and scapegoating.

The player must find another solution.

This act should transform previously optional areas into narratively relevant locations.

# ACT IV — THE VALLEY

This should be the largest act and should make the entire existing world matter.

The player needs knowledge, relics, alliances, or powers associated with several major regions.

Integrate:

- the kingdom
- the Elder Tree
- the fairy court
- the Hermit
- mountain villages
- waterfalls
- the Old Bear's cave
- goblins
- the Goblin King
- ruined sites
- the Beacon
- the Black Pool
- hunters
- Maren
- Wick
- the King
- fairy children
- possibly an ancient drowned or buried structure

The player should need several components, but avoid turning the story into a checklist of six identical fetch quests.

Each region should test a different gameplay system.

Example structure:

### Elder Tree
Traversal challenge.

The player must climb or navigate high platforms using advanced movement.

Reward:
- lore
- traversal upgrade
- ritual knowledge
- ancient inscription

### Fairy Court
Exploration and rescue progression.

The number of rescued fairy children affects cooperation.

Reward:
- Rose Compass improvements
- advanced air movement
- protection from supernatural effects
- alternate ending option

### Old Bear / Ancient Wood
Combat + environmental storytelling.

The bear should protect or sit near something important rather than exist purely as a boss.

Possible twist:
the bear is guarding an old seal or burial site.

### Mountain Villages
Social questline + survival/traversal.

Players gain an old story, relic, or material only by helping the settlement.

### Goblin territory
Combat + choice.

The Goblin King should become more than a respawning large goblin.

Potentially reveal that goblins fear the Black Pool entity too.

Some goblins may worship it; others may avoid it.

Consider:
- aggressive faction
- frightened faction
- goblin shaman
- goblin war camp
- temporary truce possibility
- alternate combat route

Do not make goblins suddenly eloquent political philosophers unless it fits the game's tone.

### Waterfalls
Secret access route / hidden shrine / ancient chamber.

Traversal and swimming should matter.

### Kingdom
Political consequence.

The King must decide whether to trust the player regarding the supernatural threat.

Hale's former authority may have supporters.

Some guards may resist.

The player’s prior reputation should affect dialogue.

# ACT V — THE FINALE

The final act should center on the Black Pool or what lies beneath it.

Potential direction:

An ancient entity, force, sealed ruin, drowned god, forgotten spirit, or folkloric presence lives beneath or beyond the pool.

Avoid generic giant demon design.

Aim for eerie folklore.

The finale should require the player to use multiple systems acquired throughout the game:

- combat
- traversal
- swimming
- stamina
- air movement
- environmental navigation
- possibly multiple weapons
- prior alliances
- fairy progression
- boss rewards

Consider multiple solutions.

Possible endings:

1. destroy the entity
2. reseal it
3. bind it through the Beacon
4. bargain with it
5. use the fairy court's solution
6. expose that the kingdom itself was built around the seal
7. sacrifice something non-human rather than a person
8. refuse all ritual logic and collapse the structure containing it

Do not force branching if implementation risk becomes too high.

At minimum, implement two distinct resolution paths if they can be made reliable.

The ending should visibly alter the valley.

# PART III — ENEMY VARIETY

The current enemy ecosystem needs meaningful expansion.

Do not simply duplicate existing enemies with more HP.

Target approximately 6–8 distinct hostile archetypes total.

Preserve:

- goblins
- Goblin King
- slimes
- larger slimes
- Old Bear

Add several enemies with distinct combat logic.

Recommended additions:

## Goblin Archer
Behavior:
- maintains range
- retreats if approached
- fires projectiles
- vulnerable during reload
- tries to occupy elevated positions
- weak in melee

## Goblin Shieldbearer
Behavior:
- blocks frontal attacks
- can be broken by heavy attacks, aerial attacks, flank attacks, or shield timing
- protects nearby goblins
- slower movement

## Wolf Pack
Behavior:
- circles player
- attacks from alternating directions
- retreats after missed lunges
- becomes more aggressive if another wolf is injured
- occurs primarily in mountain/forest regions

## Bog Wraith
Behavior:
- appears around Black Pool/wetlands, mainly at night
- semi-transparent
- briefly disappears/reappears
- attack telegraph is strongly visual/audio-based
- vulnerable after attacking
- possibly resistant to ordinary horizontal attacks

## Giant Spider
Behavior:
- forest/ruin enemy
- web projectile or web field slows movement
- can climb on geometry if feasible
- leap attack
- low health but disruptive

## Stone Troll / Moor Giant
Behavior:
- very slow
- massive stagger attacks
- high poise
- must be dodged rather than face-tanked
- obvious attack windups
- weak points after slam

Alternatively, if troll complexity is too high, implement a corrupted knight or pool creature.

Each region should have an enemy identity.

Suggested distribution:

- roads / plains at night: goblins
- wetlands: slimes + wraiths
- forest: wolves + spiders
- mountains: wolves + larger creature
- supernatural late-game zones: wraiths / corrupted enemies

# PART XXIII — SPECIFIC IMPLEMENTATION GUIDANCE

Prefer data-driven systems.

For example, new discoveries:

```js
const DISCOVERIES = {
  blackPool: {
    name: "The Black Pool",
    found: false,
    x: ...,
    z: ...
  },

  drownedChapel: {
    name: "The Drowned Chapel",
    found: false,
    x: ...,
    z: ...
  }
};
```

World-state flags:

```js
const WORLDSTATE = {
  marenFreed: false,
  haleExposed: false,
  pyreDismantled: false,
  blackPoolAwake: false,
  goblinKingDefeated: false,
  bearDefeated: false,
  fairyCourtOpen: false,
  finaleStarted: false,
  ending: null
};
```

Story acts:

```js
const STORY_ACT = {
  ARRIVAL: 0,
  CHAMPION: 1,
  BLACK_POOL: 2,
  AWAKENING: 3,
  VALLEY: 4,
  FINALE: 5,
  COMPLETE: 6
};
```

Enemy behavior should use state machines consistent with existing goblin logic.

Example:

```js
enemy.state =
  "idle" |
  "alert" |
  "chase" |
  "windup" |
  "attack" |
  "recover" |
  "stunned" |
  "flee";
```

Do not put complex AI inside one enormous conditional if it can be reasonably structured.

Bosses should have explicit phase state.

Example:

```js
boss.phase = 1;
```

# PART XXV — DEFENSIVE CODING

Use guard clauses.

Example:

```js
if (!npc || !npc.mesh || !npc.pos) return;
```

Clamp dangerous state.

Example:

```js
P.hp = clamp(P.hp, 0, P.maxHp);
P.stam = clamp(P.stam, 0, maxStamina());
```

Check finite coordinates:

```js
function validPos(v) {
  return v &&
    Number.isFinite(v.x) &&
    Number.isFinite(v.y) &&
    Number.isFinite(v.z);
}
```

If player position becomes invalid:

- log error
- recover to last safe position
- do not allow renderer/camera state to cascade into NaN

Maintain a safe player position periodically.

Example concept:

```js
if (P.grounded && validPos(P.pos) && !insideInvalidGeometry(P.pos)) {
  lastSafePlayerPos.copy(P.pos);
}
```

If world collision catastrophically fails:

```js
if (!validPos(P.pos) || P.pos.y < WORLD_MIN_Y) {
  console.warn("Recovering player from invalid position");
  P.pos.copy(lastSafePlayerPos);
  P.vel.set(0, 0, 0);
}
```
